# Карта UX: прототип Rewards / Activity

Документ для нас: **крупные блоки** того, что видит пользователь внутри рамки устройства (без демо-панели симулятора сбоку). При правках верстки или копирайта ориентируйся на это, чтобы не ломать смысл экрана.

Формат блока:

- **Назначение** — зачем блок пользователю.
- **Вход** — откуда пользователь сюда попадает / что его формирует.
- **Основное действие** — что можно сделать в блоке.
- **Следующий шаг** — куда уводит типичный сценарий.

---

## Экран «Exness Rewards»

### Верхняя панель (назад, заголовок, информация)

| Поле | Содержание |
|------|------------|
| **Назначение** | Ориентация: где пользователь, выход назад, доступ к справке/инфо о программе (в прототипе кнопки без навигации). |
| **Вход** | Открытие раздела наград. |
| **Основное действие** | Назад; открыть информацию (задумано продуктом). |
| **Следующий шаг** | Скролл к контенту или использование hero-блока ниже. |

### Hero: статус и прогресс тира

| Поле | Содержание |
|------|------------|
| **Назначение** | Показать **текущий уровень** (статус) и **условие удержания** (сколько EXD нужно «заработать» к цели, с учётом уже заработанного и ожидающих loyalty-начислений). Отдельно — срок действия статуса («дней осталось»). |
| **Вход** | Тот же экран; данные приходят из состояния приложения (в прототипе — из сценария жизненного цикла). |
| **Основное действие** | Визуально оценить статус и прогресс; в макете предусмотрен переход к деталям тира (в прототипе кнопка без отдельного экрана). |
| **Следующий шаг** | Понимание, нужно ли «докручивать» EXD; переход к кошелькам и спискам ниже. |

**Зависимость для правок:** логика полосы прогресса завязана на «заработанный EXD к цели» и loyalty в Upcoming; кэшбэк в USD в этот прогресс не входит — иначе сломается смысл «Earn N EXD».

### Карусель кошельков (Available rewards / Trading)

| Поле | Содержание |
|------|------------|
| **Назначение** | Два баланса: **что можно перевести на торговый счёт** и **что уже на торговом** (или связанный кошелёк). Разделение «доступно к действию» vs «уже в работе». |
| **Вход** | Скролл с главного экрана. |
| **Основное действие** | Перевод доступных наград на счёт (если сумма > 0); вторичное действие у торгового кошелька — задуманный переход дальше (в прототипе заглушка). |
| **Следующий шаг** | Флоу перевода или просмотр деталей торгового баланса. |

**Зависимость:** кнопка перевода дизейблится при нуле — не показывать активным при пустом балансе, иначе ожидание сломается.

### «How to earn rewards»

| Поле | Содержание |
|------|------------|
| **Назначение** | Краткое **обучение / мотивация**: как вообще получать награды (торговля, EXD, рост статуса). |
| **Вход** | Скролл под кошельками. |
| **Основное действие** | Прочитать; в прототипе блок в основном информационный. |
| **Следующий шаг** | Переход к спискам начислений ниже. |

### «Upcoming»

| Поле | Содержание |
|------|------------|
| **Назначение** | Показать **ещё не зачисленные** начисления (loyalty, кэшбэк и т.д. по сценарию), чтобы пользователь видел будущие деньги и мог открыть детали. |
| **Вход** | Скролл; блок скрывается, если список пустой. |
| **Основное действие** | Тап по строке → детальная карточка (bottom sheet) с типом операции. |
| **Следующий шаг** | Модалка деталей; для пачек — список ордеров внутри модалки. |

**Зависимость:** суммы loyalty здесь могут учитываться в прогрессе тира в hero — менять одно без другого опасно для согласованности.

### «Lifetime cashback»

| Поле | Содержание |
|------|------------|
| **Назначение** | **Один агрегат за всё время** по кэшбэку в валюте; якорь доверия и долгосрочной ценности программы. |
| **Вход** | Скролл; заголовок секции ведёт в ленту с фильтром по кэшбэку. |
| **Основное действие** | Тап по заголовку секции → полная **Activity feed** с предустановленным типом «кэшбэк». Тап по карточке суммы в прототипе не отделяется — основной переход через заголовок. |
| **Следующий шаг** | Экран ленты с отфильтрованными событиями кэшбэка. |

### «Activity feed» (превью на главной)

| Поле | Содержание |
|------|------------|
| **Назначение** | **Последние операции** без ухода с главной; быстрый доступ к деталям и к полной истории. |
| **Вход** | Скролл; заголовок секции открывает полную ленту без фильтра по типу (все типы / дефолтные фильтры). |
| **Основное действие** | Тап по строке → та же модалка деталей, что и в полной ленте; тап по заголовку → экран **Activity feed**. |
| **Следующий шаг** | Модалка или полный список с фильтрами. |

**Зависимость:** превью и полная лента должны опираться на **одинаковую модель строки и модалки**, иначе пользователь увидит разное поведение на главной и в ленте.

## Экран «Activity feed»

### Верх: назад

| Поле | Содержание |
|------|------------|
| **Назначение** | Вернуться на **Exness Rewards** без потери контекста приложения. |
| **Вход** | Переход из превью ленты, из Lifetime cashback или иной deep-link в прототипе. |
| **Основное действие** | Назад. |
| **Следующий шаг** | Главный экран наград. |

### Заголовок страницы

| Поле | Содержание |
|------|------------|
| **Назначение** | Ясно обозначить **полную историю активности**, а не превью. |
| **Вход** | Открытие экрана ленты. |
| **Основное действие** | Только чтение. |
| **Следующий шаг** | Выбор фильтров или скролл списка. |

### Фильтры «Type» и «Date»

| Поле | Содержание |
|------|------------|
| **Назначение** | Сузить список по **типу события** (награды, кэшбэк, переводы, прочее) и по **периоду** (всё время, последние 7/30 дней, текущий месяц). |
| **Вход** | Экран ленты; при входе с Lifetime cashback тип может быть предустановлен на кэшбэк. |
| **Основное действие** | Открыть sheet, выбрать значение; список пересчитывается. |
| **Следующий шаг** | Отфильтрованные группы по датам или пустое состояние «нет совпадений». |

### Список по дням (группы)

| Поле | Содержание |
|------|------------|
| **Назначение** | Хронология: **события сгруппированы по дате**, чтобы было проще сканировать день. |
| **Вход** | После применения фильтров; при отсутствии данных — пустой экран. |
| **Основное действие** | Тап по строке → модалка деталей награды/операции (как на главной). |
| **Следующий шаг** | Та же **Reward detail** модалка; опционально вложенный уровень для ордеров в пачке. |

### Пустые состояния

| Поле | Содержание |
|------|------------|
| **Назначение** | Объяснить **нет транзакций вообще** vs **фильтры отсекли всё**. |
| **Вход** | Пустой источник данных или слишком узкий фильтр. |
| **Основное действие** | Понять причину; при необходимости сменить фильтры. |
| **Следующий шаг** | Смена фильтра или уход назад. |

## Модалка детали награды / операции (`RewardDetailModal`)

Общий слой поверх текущего экрана (главная или лента).

### Шапка и закрытие

| Поле | Содержание |
|------|------------|
| **Назначение** | Понять **тип сущности** (заголовок), выйти из деталки. |
| **Вход** | Тап по строке в Upcoming, превью ленты или полной ленте. |
| **Основное действие** | Закрыть по крестику или по затемнению вокруг (в прототипе). |
| **Следующий шаг** | Возврат к списку. |

### Герой: иконка, сумма, статус (чип)

| Поле | Содержание |
|------|------------|
| **Назначение** | **Главный факт**: сколько и в каком **состоянии** (например Upcoming, Credited, Activated). |
| **Вход** | Открытие модалки. |
| **Основное действие** | Быстро считать сумму и статус. |
| **Следующий шаг** | Прочитать таблицу деталей ниже или перейти к ордерам. |

### Блок полей «детали» (label / value)

| Поле | Содержание |
|------|------------|
| **Назначение** | **Прозрачность**: даты, период, счета, ссылки на пачку и т.д. |
| **Вход** | Скролл внутри модалки. |
| **Основное действие** | Чтение; без отдельных действий в прототипе. |
| **Следующий шаг** | Для пачек — блок ордеров; для простых типов — конец сценария. |

### Блок «ордера» (только для пачек loyalty / cashback)

| Поле | Содержание |
|------|------------|
| **Назначение** | Показать, **из чего сложилась сумма пачки**: список ордеров; превью последних на первом уровне, полный список во втором sheet. |
| **Вход** | Модалка с вариантом «пачка». |
| **Основное действие** | Открыть полный список ордеров; тап по ордеру → **деталь одного ордера** в том же втором слое. |
| **Следующий шаг** | Назад по уровням (ордер → список → основная модалка) или закрыть всё. |

**Зависимость:** два уровня (список / деталь ордера) должны оставаться согласованными по заголовкам и навигации «назад», иначе пользователь потеряется в стеке.

---

## Сквозные правила (чтобы не ломать UX при правках)

1. **Один контракт строки** для превью на главной, полной ленты и Upcoming: одинаковые типы модалок и идентификаторы сценариев.
2. **Прогресс тира** не смешивать с кэшбэком в USD — это разные метрики.
3. **Lifetime cashback → лента** обязана открывать согласованный фильтр по кэшбэку, иначе смысл секции «вся история кэшбэка» теряется.
4. **Пустые списки:** на главной для превью ленты — короткий текст; в полной ленте — различать «нет данных» и «фильтр пустой».
