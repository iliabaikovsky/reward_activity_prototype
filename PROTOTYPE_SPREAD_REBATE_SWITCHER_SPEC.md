# Спека: прототип-переключатель 4 вариантов Spread rebate

Цель: в рамках текущего экрана `Exness Rewards` добавить **контролы сверху** для переключения между 4 UX-вариантами размещения Spread rebate, чтобы сравнить их на **одинаковом стейте данных**.

## 1) Общий демо-стейт (единый для всех вариантов)

Используем фиксированный сценарий «зрелый пайплайн + on-hold USD»:

- Pending по программе: `60` дневных начислений
- Upcoming EXD: `+184.20 EXD`
- Upcoming USD: `+192.45 USD`
- Ближайшая выплата: `7 May 2026`
- Уже дозрело и обработано частично:
  - EXD уже зачислены: `+20.98 EXD` (`5` выплат)
  - USD не зачислены из-за отсутствия destination: `+21.40 USD` (`5` выплат, статус on-hold)
- USD destination: `Not selected`

Этот стейт нужен, чтобы во всех четырёх вариантах было видно:
- агрегаты pending,
- факт частичной обработки (EXD paid / USD on-hold),
- необходимость выбора счёта.

## 2) Контролы переключения

Размещаем отдельный блок в верхней части контента (после hero, до секций экрана):

- Заголовок: `Spread rebate prototypes`
- Подзаголовок: кратко про единый демо-стейт
- Сегмент-контрол с кнопками:
  - `V1 · In Upcoming`
  - `V2 · Flexible Upcoming`
  - `V3 · Separate Widget`
  - `V4 · Hybrid section`

Переключение мгновенное, без роутинга; меняется только зона прототипа и связанные секции.

## 3) Вариант V1 — «Всё внутри Upcoming (две строки)»

Поведение:
- В секции `Upcoming` дополнительно рендерятся 2 агрегатные строки Spread rebate:
  1. `Spread rebate · EXD upcoming`
  2. `Spread rebate · USD upcoming`
- В строках обязательно показываем:
  - сумму агрегата,
  - `60 payouts pending`,
  - `Next payout: 7 May 2026`.
- Для отражения частичной выплаты:
  - в EXD-строке: подпись `5 payouts already credited in EXD`;
  - в USD-строке: подпись `5 payouts on hold — select account`.

Задача варианта: увидеть, насколько этот паттерн читается в текущем контракте `Upcoming`.

## 4) Вариант V2 — «Гибкий Upcoming (pinned + drill-in)»

Поведение:
- Обычный плоский `Upcoming` заменяется демонстрационным блоком `Upcoming (flexible prototype)`.
- Вверху — `Pinned` строки:
  - `Weekly loyalty +4.20 EXD`
  - `Weekly cashback +5.00 USD`
  - `Spread rebate · next EXD payout +3.90 EXD`
  - `Spread rebate · USD on hold +21.40 USD`
- Ниже — кнопка `View all upcoming items`, которая раскрывает drill-in список.
- В раскрытом списке показываем смешанный список loyalty/cashback/spread (демо-строки) + краткий summary.

Задача варианта: проверить UX «закреплённое ближайшее + полный слой внутри Upcoming».

## 5) Вариант V3 — «Отдельный виджет/карточка»

Поведение:
- Секция `Upcoming` остаётся в текущей логике (без spread-строк).
- Ниже рендерится отдельный блок `Spread rebate`:
  - total pending EXD/USD,
  - `60 payouts pending`,
  - `Next payout: 7 May 2026`,
  - destination-статус `USD account is not selected`,
  - warning-строка про `+21.40 USD on hold`,
  - CTA-кнопка `Select USD account` (демо без реального действия).

Задача варианта: оценить отдельную информационную архитектуру программы как самостоятельного продукта.

## 6) Вариант V4 — «Hybrid: секция Spread rebates + последняя выплата в Upcoming»

Поведение:
- Вверху отдельная секция `Spread rebates` (стили из Figma node `48944:86622`):
  - переключатель состояния: `Account not selected / Account selected`,
  - в состоянии без аккаунта: alert `Select account for USD` + CTA `Select account`,
  - в состоянии с аккаунтом: карточка destination (`MT5 · #12345678`),
  - агрегатная карточка `Accumulated USD / Accumulated EXD` + строка `N future payouts, nearest on ...`.
- Ниже отдельная секция `Upcoming`, где показывается обычный список выплат (cashback, loyalty и последние строки spread rebates).
- Таким образом смешиваем:
  - отдельный продуктовый блок программы (как V3),
  - и присутствие последних rebate-выплат в общем Upcoming (как V1/V2 логика списка).

Задача варианта: оценить компромисс «программа как отдельная сущность + не теряем её в общем списке ближайших выплат».

## 7) Что должно быть одинаково во всех 4 вариантах

- Тот же hero/кошельки/Activity/Lifetime (кроме зоны Upcoming/виджета, где вариант меняет UI).
- Тот же демо-стейт чисел.
- Явная видимость проблемы on-hold USD.

## 8) Технический scope реализации

- Изменяем только фронтовую верстку и локальный state в `ExnessRewardsScreen`.
- Без API/персистентности.
- Без изменения текущих modal-флоу.
- Достаточно визуального прототипа «кликается и переключается».
