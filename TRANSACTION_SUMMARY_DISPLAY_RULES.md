# Правила отображения транзакций (V4 summary drill / `V2SummaryCurrencyDetailPage`)

Документ задаёт **копирайт и смысловые правила** для строк в списке выплат на экране детализации Upcoming cashback / Upcoming rewards (прототип). Реализация в коде должна следовать этим правилам.

---

## 1. EXD cashback (только в контексте **USD** / «Upcoming cashback»)

| Поле | Правило |
|------|--------|
| **Заголовок** | `EXD cashback` |
| **Дата выплаты в данных** | Ровно **одна** строка; выплата **завтра** относительно «сегодня» прототипа. |
| **Подзаголовок / line1** | `For daily trading` (короткое пояснение дневного кешбэка). |
| **Программа (фильтр)** | Относится к ветке **Loyalty** в чипе программы (как в текущем прототипе). |

**Группировка по дням:** все строки этого типа попадают в секцию **Tomorrow**.

---

## 2. Long term rebates (слоты **USD** и **EXD** по spread / долгосрочным ребейтам)

Речь о строках, которые в данных соответствуют «Cash rebates» / «EXD rebates» (не loyalty-награда и не EXD cashback).

| Поле | Правило |
|------|--------|
| **Заголовок** | Всегда **`Long term rebates`** (единый продуктовый лейбл). |
| **Даты выплат** | В прототипе **каждый календарный день** одна строка: от **+30** до **+60** дней от «сегодня» (включительно), итого 31 выплата. Ближайшая long term — через **30** дней, последняя в этом наборе — через **60** дней. |
| **Подзаголовок / line1** | `For trading on {date}` — **`date`** = календарная дата **за 60 дней до даты выплаты** этой строки (`payoutDate − 60 days`). Формат в UI: англ. локаль, напр. `Mar 13, 2026`. |
| **Программа (фильтр)** | **Long term rebates** в чипе программы. |

Одинаковая логика дат и копирайта для экранов **USD** и **EXD** (меняется только валюта суммы и иконка).

---

## 3. Loyalty rewards (начисление EXD по лояльности)

| Поле | Правило |
|------|--------|
| **Заголовок** | `Loyalty rewards` |
| **Подзаголовок / line1** | `For weekly trading` (недельный цикл продукта; **без** отдельной даты в строке). |
| **Дата выплаты в данных (прототип)** | Ровно **одна** строка; дата выплаты — **среда недели, следующей за текущей** (понедельник «следующей» календарной недели + 2 дня = среда «середины следующей недели»). |
| **Частота / сценарий прототипа** | В ленте **одна** строка с фиксированной датой выплаты в данных (ср. «середины следующей недели»). **Не** моделируем повтор каждую неделю — только эта одна запись. |
| **Программа (фильтр)** | **Loyalty** в чипе программы. |

---

## 4. UI-фильтры на том же экране

| Элемент | Правило |
|---------|--------|
| **Чип программы** | Два значения: `Loyalty` / `Long term rebates`. Дефолт: **Long term rebates**. Если выбрано **не** дефолтное значение, чип визуально в **активном** состоянии (как активный `v2MonthSwitchBtn`). |
| **Чип периода** | `All time` / `Month` / `Week`. Дефолт: **All time**. Если выбрано **Month** или **Week**, чип периода тоже в активном состоянии. **Подвыбор календарного месяца** (May / Jun / …) **не показывается** — для Month/Week якорь данных — **текущий календарный месяц** устройства/прототипа. |

---

## 5. Согласованность USD / EXD экранов

- Экран **Upcoming cashback (USD)** и **Upcoming rewards (EXD)** используют **одни и те же правила** long term / loyalty; **EXD cashback** только на USD-экране, **ровно одна** строка.
