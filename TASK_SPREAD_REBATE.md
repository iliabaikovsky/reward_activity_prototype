# Задача: блок «Daily spread rebate» (T+60)

> Рабочее название: **Daily spread rebate**. Окончательное имя — TBD (см. «Открытые вопросы»).
> Документ — первая итерация. Сначала фиксируем механику и юз-кейсы; экранную реализацию допишем после согласования.

---

## 1. Контекст программы

- За каждый **торговый день** пользователь получает выплату в размере **1% от спреда**, который он сгенерировал в этот день.
- Выплата приходит **через 60 дней** после торгового дня (T+60).
- Сумма делится на две части: **USD** и **EXD**. Точное соотношение — TBD (см. вопросы).
- USD и EXD идут в **разные места**:
  - **EXD** — зачисляются автоматически в **Available rewards** (как сейчас в прототипе для loyalty).
  - **USD** — попадают на **выбранный торговый счёт** пользователя; без выбранного счёта живой выплаты не происходит (см. раздел «Выбор счёта для USD»).
- Программа **накопительная**: каждый торговый день рождает свой собственный «будущий платёж» с собственной датой T+60. Несколько торговых дней → несколько параллельных будущих выплат.

---

## 2. Жизненный цикл одного дневного начисления

Один торговый день D → одна «pending-запись» с двумя суммами (USD, EXD).

| Стадия | Что значит | UX-роль |
|--------|------------|---------|
| **Generated (D)** | Сгенерирован дневной отчёт по спреду. Сумма зафиксирована. | Появляется новая строка в «Upcoming» с датой выплаты D+60. |
| **Maturing (D … D+59)** | Запись «зреет», ничего не меняется в сумме. | Видно в списке предстоящих; счётчик «дней до выплаты» уменьшается. |
| **Payout (D+60)** | EXD зачислены в Available rewards. USD: либо зачислены на выбранный торговый счёт, либо попали в «отложенный» статус (см. ниже). | Запись уходит из Upcoming в Activity feed как «Credited / Paid». |
| **On hold** | Подвид Payout: EXD-часть зачислена, USD-часть **ждёт выбора счёта** пользователем. | Отдельная пометка/статус в ленте; CTA «выбрать счёт». |
| **Cancelled / Reversed** *(если применимо)* | Откат начисления (нарушение условий, возврат сделки). | TBD: показывать ли в ленте, как маркировать. |

## 3. Юз-кейсы (что должно работать)

### 3.1. Ежедневная торговля без перерывов

- Каждый день → **+1 запись в Upcoming**, **−1 запись из Upcoming** (та, что дозрела).
- В стационарном режиме у пользователя в Upcoming — **до 60 параллельных записей** одновременно.
- Это **много для UI**: 60 строк одинакового типа на экране наград — не читаемо. Нужен **агрегатор** (см. раздел 5).

### 3.2. Паузы в торговле

- Пропущенные дни просто не порождают новых записей.
- Существующие в Upcoming продолжают «зреть» — пауза не отменяет уже сгенерированные выплаты.
- В ленте после паузы будут «дыры» — это нормально и **не требует** объяснения в UI.

### 3.3. Первый день / новый пользователь

- Upcoming по программе пуст.
- Нужен **пустой стейт с описанием механики** (или баннер из «How to earn rewards» закрывает эту роль — см. раздел 5.2).

### 3.4. Пользователь не выбрал торговый счёт для USD

- EXD-часть всё равно зачисляется по расписанию.
- USD-часть **повисает** в статусе «awaiting account» (не теряется).
- В блоке программы и в ленте — постоянный CTA «Выбрать счёт для USD».
- При выборе счёта — все «зависшие» USD начисляются разом или по очереди (TBD).

### 3.5. Пользователь сменил торговый счёт для USD

- Уже **зачисленные** USD остаются на старом счёте.
- Все **будущие** выплаты идут на новый счёт.
- Те, что в статусе «on hold» (ещё не выплачены, ждали счёт) — идут на новый счёт.

### 3.6. У пользователя несколько торговых счетов

- Один из них помечен как **destination для USD-rebate**. Это явный выбор пользователя.
- Смена destination — частный случай 3.5.

### 3.7. Закрытие торгового счёта-получателя

- TBD: автоматически перевести destination на оставшийся счёт vs принудительно попросить выбрать заново.
- На время «без счёта» — режим как в 3.4.

### 3.8. Нулевой день

- Пользователь торговал, но 1% спреда округлился до 0 (или ниже минимума). TBD: создавать ли запись или скрывать.

### 3.9. Возврат / откат

- Reversed запись — отдельная строка в Activity feed с отрицательной суммой (по аналогии с существующими «Cashback reversed» в прототипе).

## 4. USD vs EXD: куда и когда

| | EXD | USD |
|---|------|------|
| **Когда виден future amount** | Сразу при генерации (T) | Сразу при генерации (T) |
| **Когда зачисляется** | T+60 | T+60 (если выбран счёт) |
| **Куда зачисляется** | Available rewards (общий кошелёк наград) | Указанный пользователем торговый счёт |
| **Поведение без выбранного счёта** | Не зависит, всё равно зачисляется | Стейт «on hold», ждёт счёт |
| **Можно ли потратить раньше** | Только по общим правилам Available rewards (transfer to account) | Нет — выплаты до T+60 нет |

**Ключевой смысл для пользователя:** EXD — «универсальная валюта программы», копится в одном кошельке. USD — «возврат на торговлю», требует адреса доставки.

## 5. Изменения в интерфейсе

### 5.1. Новый блок «Daily spread rebate» на экране Exness Rewards

**Назначение:** показать суммарный pending по программе и дать вход в детали (список 60 дней, выбор счёта, история).

**Где разместить (предложение):** между **Upcoming** и **Lifetime cashback**. Аргументы:

- Логически это «то, что точно придёт» → ближе к Upcoming, но **отдельной программой**, а не строкой внутри.
- Lifetime cashback ниже остаётся «итогом за всё время» по другому источнику — порядок не ломается.

**Что показывает блок (минимум):**

1. **Заголовок** программы + chevron «детали».
2. **Сводка по pending:** сумма USD + сумма EXD, **в сумме за все ещё не выплаченные дни**.
3. **Подпись:** «N начислений ждут выплаты, ближайшее — D, последнее — D+59».
4. **Статус доставки USD:** короткий маркер «USD пойдут на счёт #12345» **или** предупреждение «Выберите счёт для USD» с CTA.
5. *(опционально, фаза 2)* **Мини-визуализация** — горизонтальная шкала «созревания» или маленький график «сколько прилетит в ближайшие 7/30 дней». Точный формат — TBD.

**Что не показываем тут:** список всех 60 строк (он ушёл в детали), исторические выплаты (это в Activity feed).

### 5.3. Поведение Upcoming в существующем виде

Сейчас Upcoming — единая лента loyalty/cashback начислений. Решение нужно по двум вариантам:

- **Вариант A: «новая программа отдельно».** Записи дневного rebate **не попадают в общий Upcoming**, они живут только внутри своего блока (5.1). Плюс: общий Upcoming не раздувается до 60 строк. Минус: дублирование смыслов.
- **Вариант B: «всё в одном Upcoming».** Записи попадают в общий Upcoming, **но агрегируются**: одна сводная строка «Daily spread rebate · N начислений · сумма» с переходом в детали. Плюс: один источник правды. Минус: ломается текущая логика «строка = один платёж».

Рабочая рекомендация: **Вариант A** — это меньше ломает текущий UX и чище для нового источника.

### 5.4. Экран / шит «Daily spread rebate detail»

Куда уходит chevron из блока 5.1. Что внутри (черновик):

1. **Header:** название программы, кнопка назад.
2. **Сводка** (повтор 5.1): итоги USD + EXD, ближайшая дата выплаты.
3. **Destination для USD:** «куда придут USD» — счёт + кнопка изменить; либо CTA «Выбрать счёт».
4. **Список pending по дням:** строка = «торговый день D, выплата D+60, сумма USD/EXD, осталось N дней». Группировка — по неделе или месяцу выплаты, чтобы 60 строк не выглядели простынёй.
5. **История выплат:** ссылка/секция «уже выплачено» → ведёт в Activity feed с предзаданным фильтром по типу «Spread rebate».

Точный формат списка (агрегация / календарь / таймлайн) — это и есть **«место для самого динамичного интерфейса»**, его прорабатываем отдельно (см. вопросы).
